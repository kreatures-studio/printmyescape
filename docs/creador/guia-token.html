PrintMyEscape Creador

Cómo crear tu token de acceso

El creador guarda los juegos en vuestro repositorio privado de GitHub. Para entrar hace falta un token: una llave que solo abre ese repositorio y que tú puedes anular cuando quieras. Se tarda unos cinco minutos.

Atajo: el formulario de GitHub ya relleno

Escribe de quién es el repositorio de juegos (la parte de antes de la barra: en estudio/juegos es estudio) y pulsa el botón. GitHub abre su formulario con el nombre, la caducidad y los permisos puestos.

Lo único que el enlace no puede rellenar es el repositorio. En «Repository access» elige Only select repositories y marca solo el repositorio de juegos (por ejemplo printmyescape-juegos). Si se queda en «All repositories», el token abre todos tus repositorios.
Abrir el formulario de GitHub

Paso a paso

  1. Entra en github.com con tu cuenta (la que tiene acceso al repositorio de juegos). Si GitHub te pide verificar tu correo, hazlo antes.
  2. Arriba a la derecha, pulsa tu foto y elige Settings.
  3. Abajo del todo en la columna izquierda, Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  4. Token name: Creador PrintMyEscape. Expiration: 90 días es un buen equilibrio (cuando caduque, se crea otro igual).
  5. Resource owner: el propietario del repositorio de juegos (tu cuenta o la organización del estudio). Si es una organización que pide aprobación, escribe para qué es; el token queda pendiente hasta que un administrador lo apruebe.
  6. Repository access: elige Only select repositories y, en la lista «Select repositories», solo el repositorio de juegos. No dejes «All repositories».
  7. Permissions → Repository permissions: pon Contents en Read and write y Pull requests en Read and write. Metadata se pone sola en Read-only. No hace falta nada más.
  8. Pulsa Generate token y copia el token (empieza por github_pat_). GitHub solo lo enseña una vez.
  9. Vuelve al creador, escribe el repositorio como propietario/nombre, pega el token y pulsa Entrar.

Para qué usa el creador cada permiso

PermisoPara qué
Contents · lectura y escrituraLeer y guardar los juegos (cada juego en su rama, juego/<nombre>), las imágenes que subes y la biblioteca.
Pull requests · lectura y escritura«Enviar al estudio»: abre una petición para que el estudio revise el juego.
Metadata · solo lecturaLo pone GitHub siempre: saber que el repositorio existe.

Seguridad

  • El creador recuerda el token en ese navegador hasta que se pulsa «Salir». Solo se envía a GitHub. Si el estudio os da un enlace con el token, el creador lo guarda y lo quita de la dirección; no reenviéis ese enlace.
  • No lo compartas ni lo pegues en otros sitios. Si crees que alguien lo ha visto, anúlalo en Settings → Developer settings → Fine-grained tokens (botón Delete) y crea otro.
  • Cada persona del equipo debería tener su propio token: así se sabe quién guardó cada cambio.

Comprobar a qué repositorios llega un token

En GitHub: tu foto → Settings → Developer settings → Fine-grained tokens → el token («Creador PrintMyEscape»). Su apartado Repository access dice a qué repositorios llega. Se puede cambiar sin crear otro: Edit, elegir Only select repositories, marcar el de juegos y Update.

Si algo falla

  • «GitHub no acepta ese token»: ha caducado, se copió incompleto o está pendiente de aprobación en la organización.
  • «No se pudo leer el repositorio»: el repositorio está mal escrito o no se eligió en Repository access (paso 6).
  • Guarda pero no puede enviar al estudio: falta Pull requests: Read and write (paso 7). Edita el token en GitHub y añádelo.
